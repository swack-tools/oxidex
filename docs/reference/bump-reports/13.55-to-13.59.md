# Retrospective refresh: ExifTool 13.55 to 13.59

**Passed on 2026-09-11 at OxiDex
[`4fb705da`](https://github.com/swack-tools/oxidex/commit/4fb705da43ec97c4c8d1786617021984e3a943e7).**
The isolated `bump-exiftool.sh` / `upgrade_transaction.py` dry run completed in
**611.006 seconds** without a generator or handwritten-runtime source edit.
The caller's source, logical/raw index and **13.59** pin remained unchanged.
No generated output was promoted to the caller.

This experiment holds the current handwritten runtime and generator source
constant, regenerates all 28 declared outputs with 13.55 in BEFORE and 13.59 in
AFTER, and builds a fresh binary in each private variant. Both binaries are
graded against the **same 13.59 oracle** and the same 193-file corpus. It measures
the effect of refreshing these generated artifacts on current runtime source.
It does not reconstruct an old OxiDex release or measure the historical work
that implemented today's runtime and upgrade tooling.

The measured extraction improvement was three Garmin file-identity values.
The large declaration diff and classifier counts below are different evidence
and do not establish thousands of implemented tags or required source edits.
The [earlier 13.58-to-13.59 exercise](./13.58-to-13.59.md) remains historical.

## Generated artifacts and independent checks

Both variants regenerated the complete manifest: **28 outputs, eight in tier 1
and 20 in tier 2**. Fourteen outputs differ byte-for-byte between the two variants:
12 Rust files and the two expression/value-conversion ledgers. Five contain
generated Rust code/data changes: binary tables, IFD tables, file-identification
tables, Composite definitions and lens alternatives. Seven Rust files change
only in full-line comments/source references. The value ledger changes only its
release stamp; the expression ledger changes verified population and provenance.
The other 14 outputs are unchanged, so changed-file counts must not stand in for
semantic changes or engineering effort.
The AFTER variant differs from committed 13.59 outputs only in the expression
ledger's fresh provenance. Write-set guards passed with no undeclared net source
changes.

The 14 skipped probes on each side are Perl-error inputs, not successful
comparisons. Every translated expression had at least one matching comparison
and zero failing comparisons. `verify.py` passed with zero binary/IFD mismatches
against each release's source. The complete GeoTIFF, DICOM and lens-alternative
verifiers also passed on both sides. GeoTIFF checked 64 names, 19 map associations
and 2,089 conversion facts; DICOM checked 5,669 entries and 1,978 UIDs per side.
Canon EF retains 239 base IDs and grows from 295 to 296 alternatives; RF grows
from 75 to 76 base IDs. Pentax/Olympus lens populations are unchanged.
These validate the selected generated facts, not all runtime walks or samples.

All **173 added tables** and **1,898 raw keys** in those new tables belong to
Garmin. No module or table was removed. Another **59 existing tables** changed
across 13 existing modules. A module/table/key census is distinct from the
classifier's field and metadata rows below.

## Static triage is a review queue

Instrument: `triage_bump.py` on the two fresh `dump_tables.pl` JSON files.

| View | AUTO | EXPR | COND | HAND | Total rows |
| --- | ---: | ---: | ---: | ---: | ---: |
| Raw report | 1,843 | 4 | 12 | 3,172 | 5,031 |
| Release rows, excluding only four `kind=standing` rows | 1,843 | 4 | 12 | 3,168 | 5,027 |
| Garmin rows | 1,729 | 0 | 0 | 3,094 | 4,823 |
| Outside Garmin and standing debt | 114 | 4 | 12 | 74 | 204 |

The raw report's **36.6% AUTO** describes its classification of rows, not the
percentage of upgrade labor automated. One declaration can create several rows.
The four EXPR rows, for example, concern one `Exif::Main` tag, 41998, whose UTF-8
Decode conversion is unsupported. The four standing Sony/Nikon generator-less
outputs are existing debt listed on every bump, not four new tasks caused here.
Other HAND/COND/EXPR rows can require verification, shared-rule work, producer
reconciliation or continued withholding; they are not all new handwritten code.

Garmin exposes a specific classifier limitation. Its new-module HAND message
says a parser/dispatch is needed, but the measured source already dispatches FIT
to `src/parsers/specialized/fit.rs`. That handwritten parser reads the first
Session message and selected fields, and is identical in both variants. The
generator also emits Garmin declarations without source edits. These facts do
not establish that the current runtime activates or consumes every declaration.
Producer-aware triage must distinguish this existing partial implementation
from no parser at all.

The IFD classifier uses emitter/refusal rules without a matching PASS ledger
supplied to this triage invocation; it therefore remains conservative about
verification-dependent facts. Legacy binary classification retains broader
shape approximations. Generated declaration, verifier result, runtime activation
and observed extraction must remain separate accounting axes.

Only `Garmin.fit` changes semantically: FileType `FITS` becomes `FIT`, extension
`fits` becomes `fit`, and MIME type `image/fits` becomes `application/fit`.
Its **114 missing occurrences remain**. The other 192 files have no semantic
comparison change; two VALUE-list reorderings normalize away. Independent
per-file review found no new omissions, changed already-disagreeing values or
EXTRA changes.

`bump_conformance_gate.py` passed both checks: zero newly disagreeing
group-qualified `(file, tag)` pairs, and MISSING growth **0**, within the raw
EXPR+COND+HAND allowance of **3,188**. The allowance includes conservative and
standing rows; it is not evidence that 3,188 new omissions would be justified.
The pair gate does not inspect changed values of already-disagreeing pairs,
and net missing growth can hide offsetting gains/losses. The independent
per-file review above supplies the stronger finding for this particular run.
No claim is made about unexercised release declarations or other corpora.
