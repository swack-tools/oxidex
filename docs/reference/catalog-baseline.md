# Pinned source catalog baseline

This page tracks the catalog generated by the repository-pinned ExifTool release.
The catalog is an inventory of source identities, not a claim that OxiDex can
read or write every entry.

## Current catalog snapshot

`catalog_snapshot.py`, executing native ExifTool 13.59 `BuildTagLookup`, records:

[Download the generated catalog snapshot](/measurements/catalog-source-13.59.json).
Every entry includes its full source table name, raw source key, variant index,
public spelling, case-insensitive identity, and source groups. The snapshot also
records the SHA-256 of its producer and every loaded ExifTool source file (168 in this capture). User configuration is disabled, and the wrapper checks that source files do not change during capture.
The snapshot records its Perl version and executable basename. The interpreter
is recorded rather than globally pinned for this catalog-only capture. A check
on another Perl must reproduce every catalog fact and source fingerprint; only
the recorded interpreter environment may differ, and both environments are
printed in the check log. This differs from executable-body dumps that require
a matching canonical Perl/deparser.
These counts are generated from the pin; they are not constants in the producer.

The native unique-name counter and the distinct-name set differ. In pinned
`BuildTagLookup.pm`, the `subdirs`/`tagExists` counting rule can increment again
when one name occurs as both a container and an ordinary tag. For example, the
native counter increments 19 times for `Comment`. A replay of that counting
rule reproduced 21,437, including 94 repeat increments across 31 names. Different
counter eligibility also contributes to the net difference. Both figures are
preserved explicitly. They must not be substituted for one another in a coverage
percentage. The catalog validator checks row and name conservation and refuses
missing, duplicate, or malformed identities.

## What is established, and what remains

This snapshot establishes the **catalog inventory**. It does not establish
source-layout coverage, generated reader/writer acceptance, or observed behavior.
The hydrated table-identity reconciliation and the earlier source/artifact join
are separate measurements:

- [Hydrated table reconciliation](../HYDRATED-CATALOG-UNIVERSE.md)
- [Source and generated-artifact accounting](source-artifact-baseline-20260914.md)

The next report must join each entry to the full hydrated `dump_tables.pl` row,
generated reader/writer artifacts, exact refusal reasons, and observed evidence.
Unjoined and unobserved states must remain explicit. No entry may disappear
because its layout, runtime protocol, or sample is missing.

Read evidence requires an OxiDex value matching pinned ExifTool under a
`Group1:TagName` identity. Write evidence requires a real write followed by a
pinned ExifTool read-back. Source-derived acceptance remains a separate field.
One fixture should cover a distinct storage/conversion behavior; tags sharing
that generated behavior need not each have a fixture. Only tags actually
exercised by fixtures may be marked observed.

## Reproduce and check

Obtain the release named by `.exiftool-version` and set `EXIFTOOL_SOURCE` to its
source directory. `EXIFTOOL_PERL` must name a compatible Perl executable. Run
from a clean checkout:

```sh
python3 tools/exiftool-tables/catalog_snapshot.py \
  --exiftool-dir "$EXIFTOOL_SOURCE" --perl "$EXIFTOOL_PERL" \
  --output docs/public/measurements/catalog-source-13.59.json --check
```

To update the snapshot after a reviewed source/pin change, replace `--check`
with `--replace`, review the identity and denominator changes, and commit the
snapshot with its report. CI runs native regeneration and refuses any difference.
The `13.59` filename identifies this snapshot; a new release gets a new versioned
snapshot and corresponding command/report update.
