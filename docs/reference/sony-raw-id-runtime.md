# Sony binary table raw-ID repair

Follow-up to the [producer recovery](./sony-plain-generator-recovery.md).
The implementation is locally validated on synthetic carriers; full real-file
acceptance and landing remain pending. ExifTool remains pinned to **13.59**.

## Problem and resulting behavior

`Sony::CameraSettings3` declares FolderNumber at raw key `276` and ImageNumber
at `276.1`. Both read the word at byte offset 276, using different masks.
The old reader grouped rows by integer offset and selected one alternative,
so ImageNumber disappeared. The producer recovery deliberately preserved and
documented that behavior before changing the runtime.

The recovered producer now emits a `RAW_TAG_IDS` array aligned with its six
tables. The opt-in `process_with_ids` reader groups alternatives by exact
native raw ID while retaining integer offsets for byte access. It validates
all table and row counts before changing output or context, preserves IDs
through recursive directories, and reports invalid metadata to the caller.
The public Sony parser propagates that error before publishing parsed output.
Legacy callers, including Sony enciphered and Minolta A100, retain `process`
and its existing grouping behavior.

All **193 existing declarations** are byte-preserved. The generated addition
contains 193 IDs, with per-table counts **55, 45, 68, 8, 8, 9**. Independent
native verification requires exact table order, row order, ID spelling and
repetition for actual conditional alternatives. It reports shared byte offsets
as facts, rather than treating every repeated offset as an alternative.

## Numeric boundaries

Generation sorts exact decimal keys and refuses unsupported spellings. Native
Perl uses numeric comparison and truncation, so exact decimal ordering alone
is insufficient: distinct keys may round to the same native number, or a
fraction may round into the next integer offset. Both cases now refuse.
The native verifier records and checks the selected interpreter's `double/8`
numeric configuration. These boundaries were found during independent review;
they are not claims that arbitrary future native key forms are supported.

## Completed local evidence

- The full CLI matches pinned ExifTool for **both fields in six synthetic TIFF
  carriers**: 1,536- and 2,048-byte CameraSettings3 blocks, each with packed
  folder/image values 0/0, 123/4567 and 999/9999. Leading zero formatting is
  preserved. This tests the containing TIFF/MakerNote path as well as the reader.
- All **68 Sony module tests** pass with all features, including five new
  shared-reader tests and the new parser regression. Controls cover byte order,
  true alternatives, no matching condition, suppression without falling
  through, recursive IDs and invalid metadata leaving prior state untouched.
- All **43 producer/verifier methods** pass. Fresh native verification checks
  six tables, 193 rows/IDs, 72 maps and one bitmap. Both the fresh Perl 5.34
  and saved genuine Perl 5.38 dumps produce the same generated file.
- Complete tier-2 regeneration and native verification pass, with zero net
  changes from the prepared generated output. The only generated difference
  from the recovery baseline is the raw-ID array.
- Exact CI Clippy passes. Independent runtime, producer, verifier and caller
  reviews found no remaining blocker. The all-features workspace run passes:
  **5,674 tests** (54 ignored) and **222 doctests** (63 ignored), with no
  failures. Formatting and whitespace checks pass.

## Remaining acceptance

Compare a fresh control and candidate on real Sony files, and run the ordinary
runtime gate. Keep source, binary, oracle and
corpus identities with the report. Do not extrapolate the six synthetic
fixtures into a corpus improvement or a new autogenerated percentage.
The producer-aware attribution inventory must separately account for recovered
producers before another paired measurement can establish the current share.
