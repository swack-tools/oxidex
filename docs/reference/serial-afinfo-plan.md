# Next: complete the two Canon autofocus table definitions

Real AudioV4 retirement merged in #758. The next goal is to make Canon AFInfo
and AFInfo2 run through the same shared serial machinery, then remove their
duplicate manual readers after the parent routes are proved.

## Starting point and measurable targets

| Measure | Verified starting point | Next completion condition |
| --- | --- | --- |
| Native alternatives | AFInfo 14; AFInfo2 16 | Keep all 30 accounted for, even when refused |
| Generated alternatives | AFInfo 9; AFInfo2 6 | Generate all supported alternatives from native source |
| Explicit omissions | AFInfo 5; AFInfo2 10 | Reach zero only after each omitted behavior is proved |
| Executable table definitions | Both blocked | Both independently verified and replayed against native behavior |
| Canon parent routing | Still blocked | A generic bridge and authenticated validators execute the child correctly |
| Canon manual readers retired | Zero | Retire duplicates only after activation and full paired output acceptance |

These are targets, not completed work. A table becoming representable does not
by itself enable Canon extraction or remove a manual reader.

## First delivery: shared behavior for complete table definitions

Extend existing shared operations rather than introducing a Canon interpreter:

- Read signed 16-bit values and arrays through the existing low-level decoder.
- Represent lengths calculated from earlier raw values, including a trailing
  addition, as typed operands generated from the native expression.
- Reuse the existing operation that saves a raw value into parser state and
  the existing integer-enum renderer.
- Add the exact native operation that turns several 16-bit words into an
  ordered list of set-bit positions.
- Preserve how supported conditions observe absent values, including native
  short-circuit behavior. `defined` must still distinguish absence. This must
  not change the separate EXIF numeric-coercion work.

The independent verifier must authenticate those facts and reject stale or
unsupported source changes. Signed values, both byte orders, empty counts,
short data, mapped/unmapped enums, multiword bit order, absent/present parser
state and hidden-field cursor advancement require actual native proof.

Native preparatory probes already establish signed arrays, negative payload
bit masks, enum output, state effects and selected hidden-field consumption.
They do not prove new Rust execution; combined compilation, native/Rust replay
and regeneration remain required. Keep any newly discovered omission explicit.

## Second delivery: prove parent routing, then retire manual code

A generic IFD-to-serial bridge must pass bounded bytes, byte order and required
parent state to the child. The current edge's boolean validation marker is not
enough: generate and authenticate the actual validation operation and operands.
AFInfo size/aspect checks and the existing unsigned-size membership validator
have distinct native contracts.

Exercise all relevant parent edges on real and constructed files, including
rejected inputs and copied-source validator changes. Only then enable the
parent route, compare fresh control/candidate output over the full corpus, and
remove the manual duplicate. Report table readiness, routing, correct rows and
retirement separately.

## Independent parent-row follow-up

Four CanonRaw parent omissions remain. FreeBytes is the smallest candidate:
represent explicit `undef` with a one-byte width so native count derivation is
possible. Native evidence shows external data uses its byte size, while the
inline form reports just one byte even when eight inline bytes exist. Prove
short-read handling before admitting the row. Success would reduce four parent
omissions to three; it would not resolve the serial child route.

RawData, JpgFromRaw and ThumbnailImage stay refused until byte materialization,
option-dependent behavior and image validation are modeled and verified.

## Work allocation and acceptance

Terra workers perform source/compiler and native-evidence work in separate
owned checkouts. One coordinator integrates the batch and reuses the shared
Cargo cache. No per-worker full build or corpus run is needed. Commit and push
reviewable checkpoints with their remaining validation explicit.

A delivery is complete only after source inventory, independent verification,
native execution proof, appropriate output comparisons and final hosted checks
pass. Publish before/after counts and build time; no project autogenerated
percentage can be inferred from these two tables alone.
